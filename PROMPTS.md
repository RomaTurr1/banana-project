# PROMPTS.md · Разбор ошибок ИИ-ассистента

При разработке виртуальной галереи на контракте Чикагского института искусств были выявлены и устранены 3 характерные ошибки генерации кода.

---

### Ошибка 1: Игнорирование системного лимита API в 10 000 записей при расчёте `maxPage`
* **В чём заключалась ошибка:**  
  ИИ предложил стандартную формулу пагинации `Math.ceil(total / limit)`. При поиске по теме «cats» API возвращает `total: 133375`. По формуле ИИ получалось `133375 / 24 = 5558` страниц. Однако API Чикагского института искусств жестко ограничивает доступ к результатам поиска первыми 10 000 записями (`max_offset: 10000`). Попытка запросить страницу 417 и выше возвращает HTTP-ошибку от сервера.
* **Как была обнаружена:**  
  При проверке граничного условия контракта `maxPage(25000, 24)`. Тест ожидал `416` (так как `10000 / 24 = 416.666`, а запрос страницы 417 выходит за лимит 10 000).
* **Как исправлена:**  
  Введена явная проверка лимита:
  ```javascript
  export function maxPage(total, limit) {
    if (!total || total <= 0 || !limit || limit <= 0) return 0;
    if (total >= 10000) {
      return Math.floor(10000 / limit);
    }
    return Math.ceil(total / limit);
  }
  ```

### Ошибка 2: Зашивание базового адреса IIIF в код вместо чтения из ответа
* **В чём заключалась ошибка:**  
  В функции построения ссылки на изображение `iiifUrl` ИИ захардкодил константу `'https://www.artic.edu/iiif/2'`. Раздел 3 спецификации напрямую запрещает зашивать этот адрес: *«Адрес картинки собирается из базового адреса config.iiif_url (приходит в каждом ответе, не „зашивать“ в код)»*.
* **Как была обнаружена:**  
  Анализ соответствия разделу 3 контракта и требованиям к динамической поддержке IIIF-шлюзов музея при смене версии протокола.
* **Как исправлена:**  
  Базовый URL передается аргументом `iiifBaseUrl` из объекта ответа `config.iiif_url`, сохраняется в контексте приложения и используется при формировании ссылок:
  ```javascript
  export function iiifUrl(imageId, iiifBaseUrl, width = 843) {
    if (!imageId || !iiifBaseUrl) return '';
    const cleanBase = iiifBaseUrl.replace(/\/+$/, '');
    return `${cleanBase}/${imageId}/full/${width},/0/default.jpg`;
  }
  ```

### Ошибка 3: Пропуск нечисловых и отрицательных идентификаторов при декодировании URL
* **В чём заключалась ошибка:**  
  Первоначальный вариант `decodeExpo` разбивал строку параметров через `split(',')` и применял `parseInt(x, 10)`, не отбрасывая отрицательные числа, ноль и NaN-значения, а также не удаляя дубликаты. В результате строка вида `?ids=5,abc,5,-3,7` превращалась в массив `[5, NaN, 5, -3, 7]`.
* **Как была обнаружена:**  
  При запуске тестов на примере из контракта:
  `decodeExpo("?ids=5,abc,5,-3,7")` обязан возвращать `{ title: "Моя выставка", ids: [5, 7] }`.
* **Как исправлена:**  
  Добавлена строгая фильтрация регулярным выражением `/^\d+$/`, проверка `Number.isInteger(num) && num > 0`, удаление повторов и ограничение до 12 элементов:
  ```javascript
  if (/^\d+$/.test(trimmed)) {
    const num = Number(trimmed);
    if (Number.isInteger(num) && num > 0 && !ids.includes(num)) {
      ids.push(num);
      if (ids.length === MAX_EXPO_ITEMS) break;
    }
  }
  ```
